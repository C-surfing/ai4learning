# Dogfooding Arc Briefs

These briefs turn the five v0.2 domains into launchable longitudinal experiments. They define **what to test**, not what the learner is expected to prove.

- `01-probability.md` — conditional evidence, base rates, representation switch, Bayesian transfer.
- `02-mathematics.md` — hidden prerequisites, roadmap repair, formal/visual representation switching.
- `03-paper-reading.md` — argument reconstruction, claim/evidence mapping, research judgment.
- `04-programming-agent.md` — system model, executable diagnosis, code/dataflow switching, neighboring failure transfer.
- `05-conceptual.md` — causal model extraction, Feynman model debugging, intervention and transfer.

## Use

1. Pick one brief because it matches a **real learning goal**.
2. Pair it with `../ARC.md` and `../SESSION.md`.
3. Fill starting hypotheses conservatively.
4. Run normal Teach/Study interactions; do not turn the learner experience into an evaluation form.
5. Record decisive evidence after each session.
6. Preserve at least one uncertainty for later retrieval/transfer rather than forcing closure.
7. Use `../PROMOTION.md` only if observed failures suggest the runtime itself should change.

These files are protocols, not evidence. Do not commit fabricated learner outcomes into them.
